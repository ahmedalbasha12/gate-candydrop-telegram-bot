# مراقب Gate CandyDrop

السكربت يكتشف أحداث CandyDrop الجديدة من واجهة Gate العامة، يجلب قواعد كل حدث وسعر العملة، ثم يحسب:

- عدد التوكنات التقديري لكل Candy.
- القيمة الإجمالية بالدولار لكل Candy.
- الربح الصافي التقديري بعد رسوم تنفيذ حجم التداول المطلوب.
- مكافأة أول تداول الثابتة وقيمتها بالدولار.
- عدد الأماكن المتبقية عند تشغيل وضع الهاتف.

لا ينفذ السكربت أي صفقة، ولا يسجّل في الأحداث، ولا يحتاج API Key.

## التثبيت

يتطلب Python 3.10 أو أحدث. لاكتشاف الأحداث عبر الـAPI فقط لا توجد مكتبات إضافية.

لاستخراج الأماكن المتبقية من نسخة الهاتف:

```powershell
pip install playwright
playwright install chromium
```

## التشغيل

فحص واحد سريع:

```powershell
python gate_candydrop_monitor.py
```

فحص مع محاكاة الهاتف، ثم إعادة الفحص كل دقيقة:

```powershell
python gate_candydrop_monitor.py --browser --interval 60
```

استخدام نسبة الرسوم المعتمدة 0.15% من حجم التداول المحتسب:

```powershell
python gate_candydrop_monitor.py --browser --fee-rate 0.0015
```

تُحفظ النتائج في `gate-monitor-data/latest.json` و`latest.csv`.

## تشغيله كبوت Telegram

النسخة المستقلة الكاملة موجودة في `gate_timeline_bot.py`. يحتوي هذا الملف وحده على منطق اكتشاف الأحداث والحسابات وبوت Telegram، ولا يستورد أي ملف Python آخر من المشروع.

1. أنشئ بوتًا من `@BotFather` وخذ الـToken.
2. انسخ `.env.example` باسم `.env`.
3. ضع Token ورقم Telegram User ID الخاص بك في `.env`.
4. ثبّت المتطلبات ثم شغّل ملف Python مباشرة.

```powershell
pip install -r requirements.txt
playwright install chromium
copy .env.example .env
notepad .env
python gate_timeline_bot.py
```

أوامر البوت:

- `/start` لوحة التحكم والأزرار.
- `/scan` فحص Gate الآن.
- `/check رابط` فحص صفحة حدث مباشرة دون API Key.
- `/events` آخر الأحداث المحفوظة.
- `/status` حالة المراقبة.
- `/fee 0.0015` ضبط الرسوم على 0.15% من حجم التداول المحتسب.
- `/stop` و`/resume` لإيقاف وتشغيل التنبيهات.

يرسل البوت تلقائيًا إشعارًا عند اكتشاف حدث جديد أو تغيّر عدد الأماكن المتبقية. استخدم `TELEGRAM_ALLOWED_USERS` لمنع الغرباء من استخدامه.

## معادلات الحساب

`Token لكل Candy = حجم المجمع ÷ إجمالي عدد الـCandies`

إذا أعادت Gate قيمة Estimated Reward مباشرةً يستخدمها السكربت بدل القسمة.

`القيمة الإجمالية = Token لكل Candy × سعر Token/USDT`

`الرسوم التقديرية = حجم التداول المطلوب (شراء + بيع) × نسبة الرسوم`

`الصافي = القيمة الإجمالية - الرسوم التقديرية`

لأن Gate تحتسب حجم المهمة أصلًا من الشراء + البيع، لا يضرب البوت الرسوم في 2 مرة ثانية. غيّر `--fee-rate` حسب مستوى VIP لديك. لا يشمل الحساب الانزلاق السعري، وقد لا يكون للرمز سعر قبل الإدراج؛ عندها تظهر القيمة `-` حتى يبدأ زوج USDT.

## ملاحظة مهمة عن «الأماكن المتبقية»

واجهة Gate الرسمية تكشف قائمة الأحداث والقواعد، لكن عدّاد `Only ... spot(s) left` قد يكون معروضًا داخل صفحة الهاتف فقط. لذلك خيار `--browser` يشغّل Chromium بعرض 390×844 ووكيل Android، ثم يستخرج العدّاد من النص الظاهر. هذا أكثر ثباتًا من الاعتماد على أسماء CSS المتغيرة.

ملاحظة: Gate/Akamai تحظر المتصفح الآلي المخفي وتعرض `Access Denied`. لذلك يستخدم البوت Google Chrome الحقيقي بوضع مرئي/مصغّر وملف جلسة دائم داخل `.gate-browser-profile`. لا تحذف هذا المجلد أثناء تشغيل البوت، ولا تشغّل نسختين من البوت في الوقت نفسه.

الإصدار الحالي يستخدم طلبات HTTP فقط في الوضع الطبيعي عبر `curl_cffi` ببصمة TLS مطابقة لـChrome، ويقرأ قائمة Ongoing من واجهة الموقع `/apiw/v2` ثم HTML كل صفحة تفاصيل. لا يفتح Chrome إلا كخطة احتياطية إذا فشلت الطلبات وكان `GATE_USE_BROWSER=1`. اجعلها `0` لمنع فتح المتصفح نهائيًا.

## إشعار توزيع المكافآت

يستمر البوت في متابعة الأحداث الحديثة بعد انتهائها. تعتبر Gate قيمة `lottery_drawing_status=1` انتظارًا للتوزيع، والقيمة `2` اكتمالًا للتوزيع. عند الانتقال من 1 إلى 2 يرسل البوت إشعار `Rewards Distributed` مرة واحدة فقط، ثم يحفظ الحالة في `telegram_state.json`. وإذا اختفى الحدث المنتهي من القائمة الحديثة، يتابع البوت صفحة التفاصيل الخاصة به مباشرةً إلى أن يكتمل التوزيع. كما يلتقط الحالة التي كان فيها الحدث محفوظًا كـ«جارٍ» ثم ظهر فجأة موزّعًا بعد إعادة تشغيل البوت.
